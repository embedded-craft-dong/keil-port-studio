# Keil Port Studio

Current source adds a read-only [project health check](docs/DOCTOR.en.md) and the initial
[SPL RTOS/component adapters](docs/SPL.en.md). `2.3.0-dev2` provides source and Windows packages; dev1 and RC6 remain available for rollback.
Also see [CubeMX regeneration protection, isolation and recovery](docs/CUBEMX.en.md).
New: [reference removal and device driver generation](docs/DRIVERS.en.md), with software I2C,
blocking hardware and DMA-completion adapters. New drivers have host protocol/compile checks,
not physical acceptance or DMA performance measurements.
Current source supports STM32F1/F4 HAL/SPL auto-filled blocking I2C/SPI and software-I2C board APIs after
explicit bus/pin selection. Automatic DMA and other STM32 families are not covered;
the generic callback mode remains available.
F1 support is included in the dev2 source and Windows packages;
compile/link and mock tests do not constitute physical-board acceptance.

The primary path is STM32 HAL + Keil generated by STM32CubeMX. Development source now
includes SPL FreeRTOS/CMSIS-V2 and RT-Thread startup plus FatFS/LwIP/TinyUSB entry integration.
Independent F407/AC5 board tests cover RTOS/LVGL combinations, RAM filesystems, UDP loopback
and TinyUSB CDC echo/HID enumeration; not every component or hardware combination is validated. Read the
[scope and preflight checks](docs/SUPPORT.en.md).
A CubeMX project does not imply that every board configuration has been verified.

See the [hardware validation matrix](docs/HARDWARE-MATRIX.en.md) for tested configurations and remaining requirements.

Middleware and project management for Keil MDK `.uvprojx/.uvproj` projects:
private component copies, per-file selection, modification previews and transaction recovery.
Components include FreeRTOS/CMSIS-RTOS2, RT-Thread, LVGL, FatFS, LittleFS, LwIP,
TinyUSB, SEGGER RTT, CMSIS-DSP and peripheral-lock templates. Generated scaffolding
is not a completed hardware driver.

## Getting started

- Portable Windows build: extract the complete Windows ZIP and double-click
  `KeilPortStudio.exe`. Keep `_internal` beside it; copying the EXE alone will not work.
  End users do not need Python.
- Source: Python 3.8+ with Tkinter, then `python keil_port_tool.py`.
  Keep the adjacent `kps_core/` folder; do not copy only the entry-point PY file.
  Use `python keil_port_tool.py --help` for CLI options. Build packages are not runtime requirements.
- The upper-right `zh-CN / en` control selects and remembers the interface language.
  Component/file selections survive switching. Paths, macros and raw compiler output
  are not translated; some backend diagnostics remain Chinese.
- Footer **Guide** opens offline interface, post-porting and Git guides.

## Important limitations

Back up and close the selected Keil project first. General file addition references
existing files; middleware migration makes private copies. Choose one RTOS per project.
RT-Thread integration currently targets a Cortex-M4 kernel, not the complete BSP/package system.
The tool does not update CubeMX `.ioc` or provide complete CMSIS Solution/RTE management.
Display, SD/Flash, PHY, USB, DMA/cache and interrupts need board-specific implementation.
Successful compilation is not runtime validation. Recorded hardware results cover
specific test configurations, not all devices, versions or combinations.
Known limitation: GPIO-controlled USB Host VBUS shutoff failed on the test board;
the cause is unresolved. Normal thumb-drive I/O and physical power-loss retention
passed separately. A clean Windows installation without Python/Git has not been tested.

Git defaults to the current project, with folder switching. Installation and remote
operations require confirmation. No credentials are stored or uploads performed automatically.
Windows artifacts are unsigned: verify SHA256 and follow your organization's security policy;
do not disable protection to run them.
