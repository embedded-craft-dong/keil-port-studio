# STM32 标准外设库：首批适配（开发版）

[English](SPL.en.md)

`2.3.0-dev1` 源码与 Windows 预发布包包含此功能；旧 RC6 EXE 不含新增功能。
这不是“所有标准库工程一键可运行”：首批覆盖 FreeRTOS 原生 API 和 CMSIS-RTOS V2 的
启动接入（Cortex-M3/M4），以及 RT-Thread 5.2.2 单核启动（Cortex-M4）。
实板证据目前仅为 STM32F407ZGT6 + AC5；其他组件组合逐项验收，非 STM32 暂未开放。

## 新增组件支持

### 9 月 26 日：LAN8720A 真实网口

四个独立无 HAL 工程使用工具生成的 LwIP 启动/系统适配，接入私有供应商 SPL MAC 驱动及
有界 DMA 描述符适配。逐一备份、烧录校验、显式复位后，通过静态 IPv4 直连检查：
每种模式 4 次 ping、80 个 UDP 包（33910 字节）和 57852 字节 TCP 内容逐字节一致。
另外各执行 60 秒 UDP/TCP 同时收发，以下数字仅统计并发段：

| 模式 | UDP 包 | UDP 字节 | TCP 字节 |
| --- | ---: | ---: | ---: |
| 裸机 | 19310 | 28424320 | 221184 |
| 原生 FreeRTOS | 16408 | 24152576 | 229376 |
| CMSIS-V2 启动 | 16133 | 23747776 | 221184 |
| RT-Thread | 16302 | 23996544 | 253952 |

各轮主机数据与板端计数一致，心跳持续，失败、描述符丢帧、发送超时计数为零。
CMSIS-V2 另在核对运行镜像后仅软件复位、未重新烧录，重复完整基础收发检查通过。
这是正确性/持续运行检查，不是峰值吞吐量基准。构建分别为 0 错误、17/25/25/27 警告。
RTOS 使用 32 KiB 内核堆和 4 KiB TCP/IP 线程栈；这些是测试预算，不是产品默认值。

实测发现并修正的是板级适配和测试回显程序：供应商默认关闭广播导致 ARP 失败；
UDP 计数在发送加头后取长度；TCP 整包发送假设遇到有限发送缓冲而永久重试。
修正为接收广播、发送前记录载荷长度、分段发送及 sent/poll 续传后按原强度复测通过。
另有宿主 C 测试覆盖 pbuf 所有权、重试不重复、延迟关闭和错误清理；旧失败记录保留。
这些不代表工具原本自动生成了完整网卡驱动或 TCP 服务。

测试前断开 PA2 上的无线串口 RX 线，以避免 UART2_TX/ETH_MDIO 冲突；用 SWD 记录状态，
不修改电脑 Wi-Fi、IP、防火墙或共享设置，不读写 SD/NOR。未同时运行 LVGL/存储/USB，
未验收热拔网线恢复、DHCP、IPv6、HTTP/MQTT/TLS 或其他 PHY/MCU。

### 9 月 26 日：真实 SD 与 NOR 存储增补

通过实际工具安装 FatFS + LittleFS，再接入私有板级驱动的独立无 HAL 工程，
裸机、原生 FreeRTOS、CMSIS-V2、RT-Thread 四种模式均已烧录校验并通过：
真实约 8 GB SD 卡和 16 MiB SPI NOR 的文件写入、同步、追加、重挂载、逐字节读回；
每种模式再软件复位，执行只读持久化校验。两介质最终文件均为 8962 字节，
主机计算与板端读回 CRC32 均为 `1197FD2E`，错误计数为零、心跳继续增长。
随后用户确认全部断电重上电，保留的 RT-Thread 固件通过只读校验：两介质 CRC 不变，
SD 写入、NOR 编程与擦除计数全为零，心跳继续增长。此项仅属于 RT-Thread 该固件的
完整断电验收，不扩展为另外三种模式各自已做断电试验，也不是写入中掉电故障注入。

SD 不格式化，仅覆盖专用测试文件；NOR 访问限制在前 512 KiB。使用 SDIO 3 MHz
单扇区轮询和 SPI 2.625 MHz，单测试线程，不宣称高速 DMA、并发物理 I/O 或长期耐久通过。
构建均为 0 错误，四模式分别保留 5/6/6/8 条原例程或上游告警。
主栈/工作线程栈为 8 KiB，RTOS 堆为 32 KiB，均属测试配置而非通用推荐默认值。

准备过程中修正了供应商驱动错误返回未恢复中断屏蔽、长文件名未启用、测试任务缺少
错误钩子和调试邮箱应答竞态；失败日志保留，不计入通过结果。真实 NOR 使用精确 JEDEC
识别，不跳过容量与边界检查。SWD 状态与主机数据比对是判据，无线串口仅接受 CRC 正确的日志。
这证明所列组件及该板级适配可运行，**不意味着工具已经自动生成任意 SD/NOR 驱动**。

### 9 月 26 日：混合组件的重复移植与卸载

修复了相邻组件在同一个主循环中互相触发归属误报的问题。新安装记录只拥有实际插入的
include、初始化和轮询代码，不再拥有整段共享循环；卸载前仍验证准确内容和入口位置，
被修改、移到条件分支或重复的代码不会被盲目删除。用户已有的 include 和业务代码保留。
同值配置宏也不再仅为对齐空格而重写，联合移植的第二次执行可以保持工程和入口字节不变。

验证包含三组件的全部 6 种卸载顺序、裸机/原生 FreeRTOS/CMSIS-V2/RT-Thread 入口，以及
真实 manifest 的安装、重复执行和卸载。真实 SDK 的 FatFS + LwIP + TinyUSB 裸机联合工程
AC5 编译 0 错误、23 警告；另一个独立副本依次卸载 LwIP、FatFS、TinyUSB，每次都保留
用户添加的计数代码、通过剩余组件归属检查和重新编译（分别 0 错误、11/11/5 警告）。
本轮是工具与构建验证，未烧录该联合副本，也未新增物理存储/网络运行结论。

旧开发版安装记录不会被静默“重新信任”。若旧按行归属记录因组件重叠触发
`OWNED_STARTUP_DRIFT`，先完整备份并核对差异，再预览原安装事务的回滚和重新移植。
后续已有业务修改时不要直接回滚，更不要删除 `.keil-port-tool/manifest.json` 绕过保护。

#### 用户仍需完成的部分

- **FatFS**：当前适配 ST `ff_gen_drv` 布局及 `ff_mutex_*` 系统接口，不自动兼容所有旧版本。
  SPL + FreeRTOS 使用原生互斥锁后端，不依赖 HAL 或 CMSIS 包装层；RT-Thread 使用自身后端。
  `MX_FATFS_Init()` 只登记磁盘驱动。先配置真实介质，再在任务中挂载；裸机在主循环前挂载。
  工具保留已有 RTC、超时设置；`FF_FS_TIMEOUT` 的单位是内核 tick，不是固定毫秒。
  检查 `FIL`、局部读写数组、LFN 和日志占用的**主栈/任务栈**，不能只看剩余堆。
  本轮裸机用例原有 1 KiB 栈曾越界破坏 RTT 缓冲区；改为 4 KiB 并加入栈底哨兵后复测通过。
  4 KiB 只是该用例参数，不是所有应用的统一推荐值。
- **RTT**：本轮通过 ST-Link 读取控制块/环形缓冲，确认日志持续更新。没有验证 J-Link 软件或
  所有 printf 重定向。非阻塞 SKIP 模式在缓冲区满时会丢日志，需要及时读取或自行选择策略。
- **LwIP**：裸机必须提供单调毫秒 `LwIP_Platform_Millis()`；NO_SYS 默认单主循环所有者，
  IRQ 只通知/排队，不直接调用协议栈。真实 `NetworkDriver_*`、PHY、DMA 和缓存处理仍需 BSP。
  UDP 回环走真正协议栈，但不访问网卡，不验证 DHCP、TCP、网线或收发中断。
- **TinyUSB**：旧 SPL USB 设备头兼容桥仅开放 F405/F407/F415/F417，补齐并检查控制器基址、
  端点数和 FIFO 大小。其他型号拒绝猜测。仍需实现 48 MHz 时钟、GPIO、IRQ、VBUS/供电适配；
  下述 Device 实测用了专门的板级适配，不是任意工程自动可运行，也不是 Host 验收。
  RT-Thread IRQ 要正确登记中断进入/退出；已有用户配置不会被静默覆盖。

#### 本批实板记录

每次均先备份，再烧录校验、显式复位；无线 UART 只接收 CRC32 校验通过的行。
FatFS 使用 64 KiB RAM FAT12 磁盘，执行格式化、挂载/重挂载、257 字节文件写入、同步、关闭、
读回比较；**未访问实际 SD 或板载 Flash**。裸机约 39 秒完成 231750 轮；原生、CMSIS-V2、
RT-Thread 各约 39 秒完成每线程约 39400 轮，错误为 0，三个 RTOS 版本的竞争超时检查通过。
RTT 两次读取确认序列持续前进。RT-Thread 初版测试线程错误地“自删除后又返回”造成重复回收，
已修正测试线程退出方式并保留失败证据；没有关闭内核断言。
LwIP 原生 FreeRTOS / RT-Thread 各约 34 秒完成 33702 / 33701 轮 257 字节 UDP 回环校验，
错误为 0，空接收超时检查和串口查询通过。这些是短时功能测试，不是长期老化。

随后 TinyUSB 0.17 的四种模式均在同一块板上通过 USB1 实板 Device 检查：Windows 正常识别
CDC 与 HID 键盘接口，CDC 每版完成 3 次打开/关闭、120 次回传，共 206430 字节逐字节一致。
长度覆盖 1/63/64/65/257/1024/4096/8192 字节，包含零字节及全部字节值，另有延迟应用读取。
每版约 37 秒监控中没有复位，USB IRQ 持续服务，CRC 无拒收，串口查询通过。原生/CMSIS-V2/
RT-Thread 的最小 USB 栈余量分别为 442/440/450 个 32 位字，剩余堆为 10360/10360/14040 字节；
裸机用 4 KiB 主栈，栈底哨兵完整。这不代表最坏栈深度或长期稳定性保证。
板级代码显式配置 PA11/PA12、48 MHz PLL 和真实 IRQ；USB1 单路总线供电，没有使用未接的
PA9 VBUS 检测。**不把禁用 VBUS 检测的测试配置直接用于自供电产品**。
HID 只验证系统枚举，未发送键盘报告；未验证 MSC/MIDI/Vendor/Host、高速 USB 或其他芯片。
裸机版另通过 3 次软件复位：每次都重新识别并回传 8192 字节，10 条状态采样与串口查询
通过，CRC 无拒收、栈底哨兵完整；这不是完全断电恢复验证。

## 与 CubeMX 模式的区别

- 通过 Target 中的 `USE_STDPERIPH_DRIVER` 和 STM32 Device 识别，不以目录名猜测。
- 从选中 Target 实际启用的 C 文件定位唯一 `int main(void)` 和 `void SysTick_Handler(void)`。
  文件可在 `User/`，也可自定义名称；不扫描旁边工程、历史备份或整个工作区。
- 不要求 `.ioc`、HAL、`USER CODE` 标记，也不伪造 CubeMX 标记。
- 当前共享启动文件的 SPL 自动接入要求选择全部 Target；不同硬件/不同入口请分工程处理。
- 仍按事务预览、复制库副本、写入、记录源码补丁归属，支持安全与恢复。

## 使用前必须处理

1. 先确认裸机 SPL 工程自身能够编译、运行，启动文件、时钟和外设已配置正确。
2. 确认 `main` 的初始化是直线执行，随后有唯一的顶层 `while (1) { ... }` 或
   `for (;;) { ... }`。条件启动、多入口、复杂跳转拒绝自动处理。
3. SysTick 处理函数必须为空。FreeRTOS 的 SVC/PendSV 必须为空或由端口弱符号提供。
   RT-Thread 首批接入要求同一中断文件有空 PendSV，以及空或仅 `while(1){}` 的 HardFault；
   这两个向量交给 RT-Thread 汇编端口，SVC 不改。自定义异常处理不会覆盖。
4. 检查 `delay.c/SysTick.c`：旧例程常直接重装或关闭 SysTick。必须先改用独立定时器，
   或在支持 DWT 的器件上实现短忙等延时。任务等待用 `vTaskDelay/osDelay/rt_thread_mdelay`。
   工具会阻止可见的 SysTick 寄存器写入及配置调用，但不具备完整调用图/预处理能力；
   头文件内联、宏别名、直接地址写入、第三方二进制也要人工审查。
5. SPL 中使用 `NVIC_PriorityGroup_4`，检查所有调用 RTOS API 的中断优先级。
   不能只修改分组名：原先的抢占/子优先级含义可能改变。工具不会替你重分配所有外设优先级。

## CMSIS-RTOS V2：不要混用 Core 头文件

标准库历史工程通常包含较旧的 CMSIS Core。不能只补一个 `cmsis_compiler.h` 或
`cmsis_armcc.h`：它可能与旧 `core_cmFunc.h` 重复定义底层指令。

准备同一发行版 CMSIS_5（建议与本工具既有固定依赖一致的 5.9.0）：

- 将完整 `CMSIS/Core/Include` 头文件集放入工程的独立 CMSIS Core 目录，确保实际生效，
  移除混用旧 Core 的 Include 引用。保留芯片对应的 ST 设备头文件、启动汇编和 system 文件。
- 放入 `Libraries/CMSIS/RTOS2/Include` 和 `Libraries/CMSIS/RTOS2/Source/os_systick.c`，
  保留这些第三方文件的许可证。其他已有受支持 CMSIS 目录布局也可以被发现。
- 先重新编译裸机工程；升级 Core 是明确的用户操作，工具不会静默覆盖供应商 SDK。
- 启用 CMSIS-V2 后工具加入设备头文件定义、开启 C99/GNU（在预览列出），并在没有
  `RTE_Components.h` 时生成最小兼容头。它不选择 Pack，不添加 `_RTE_`，不是 RTE 管理器。

```powershell
python keil_port_tool.py .\Template.uvprojx --freertos .\SDK\FreeRTOS-Kernel --dry-run
```

## RT-Thread 5.2.2（Cortex-M4 单核）

```powershell
python keil_port_tool.py .\Template.uvprojx --rtthread .\SDK\rt-thread-5.2.2 --dry-run
python keil_port_tool.py .\Template.uvprojx --rtthread .\SDK\rt-thread-5.2.2
```

不能与 FreeRTOS 共存。工具在真正的标准库 main 中加入 `MX_RTTHREAD_Init()`，不要求
CubeMX 标记；该历史命名不代表依赖 CubeMX。在 `RTThread/App/rtthread_app.c` 的
`RTThread_DefaultTask()` 中编写业务或创建其他线程，此时内核和堆已初始化。
`RTThread/Config/rtconfig.h` 配置堆/栈，首批端口要求 1000 Hz。优先级数字越小越高，
栈大小单位为字节。不要再启用 `RT_USING_USER_MAIN` 或二次初始化堆/调度器。

普通 RT-Thread 接入不强制升级旧 CMSIS Core；若同时使用新版 CMSIS-DSP，必须像上面的
CMSIS-V2 一样使用完整、统一的现代 Core 头文件（DSP 本身不需要 RTOS2 包）。
DSP 裁剪会检查聚合源码中可见的函数和表依赖，并报告要补选的模块。例如 Statistics
需要 FastMath，后者还需要 CommonTables。工具不会擅自勾回取消的模块。这是保守源码检查，
不是完整 C 预处理器；自定义条件裁剪也可能要求补选，应以实际链接和运行验收为准。

## 移植之后在哪里写业务

普通 SPL 目录下默认生成 `Application/freertos_app.c` 和 `.h`：

- 在 `MX_FREERTOS_Init()` 创建任务和同步对象；名字仅为兼容入口，不代表需要 CubeMX。
- 在 `StartDefaultTask()` 或你自己的任务函数中写业务。
- **原 main 的无限循环内容仍保留，但启动调度器后不再执行。必须把业务迁入任务。**
  不会自动搬运局部变量或把整个旧循环套进一个任务，避免改变生命周期和栈需求。
- 工具在初始化之后、旧无限循环之前更新 `SystemCoreClock`、创建任务并启动调度器。
  启动意外返回时停留于故障等待，检查堆、断言位置，不继续跑旧裸机业务。
- 确认初始化阶段没有重新占用 SysTick 的函数；运行中不要再次调用旧 `SysTick_Init`。
- 同一屏幕由一个任务访问，或自行加互斥；本适配器不自动生成真实 LCD/触摸驱动。

重复运行不重复插入启动代码；如果修改了工具拥有的启动段，会拒绝盲目覆盖。
卸载也只撤销清单记录的补丁；业务修改冲突时停止并保留文件。

### 遥测完整性补强

无线串口不仅会丢整行，也可能丢掉数字中的字符而留下格式正确的记录。因此后续联合测试
为每一行加入板端 CRC32，电脑只解析校验通过的记录，原始日志与拒收行另行保留；不会
修补缺字后把它算作通过。复位测试以校验通过的启动标记划分运行批次，拒绝重复启动或
计时倒退，避免无线模块缓冲的复位前记录与新启动记录混算。遥测校验是测试固件功能，
并非工具自动给用户应用加入的日志协议。

加校验后的 RT-Thread 联合固件另通过 5 分钟连续运行和 3 次软件复位（各采集 45 秒）：
基本错误、LVGL 断言和后台锁失败均为 0，GUI 调用约 50 次/秒；连续段最大循环间隔
22 ms、LVGL 处理 6 ms，RTOS 剩余堆始终 10656 字节，LVGL 最小剩余堆 25116 字节。
连续段接收 1361 条校验通过、70 条拒收记录；复位段合计 612 条通过、28 条拒收，
每段串口查询都得到有效回应。这是短时运行和热复位验证，不是掉电或长期老化测试。
