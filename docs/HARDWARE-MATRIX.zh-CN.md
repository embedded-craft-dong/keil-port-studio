# 实板验证矩阵

[English](HARDWARE-MATRIX.en.md)

更新：2026-09-22。平台为普中 STM32F407ZGT6、ARMCC 5.06 update 7、板载 LAN8720、
16 MiB SPI NOR、约 8 GB SD、外接 SPI LCD、USB FS Device。UART2 使用无线串口链路。
每次烧录均校验并复位；用户原工程未改动。测试使用明确的板级适配，不声称能自动推断接线。

## 9 月 22 日 USB Host 验证增补（RC4 起纳入发布，旧 RC3 包不包含）

USB3 接实物 U 盘，USB2 单路供电，USB1 留空。U 盘实际为 16,122,970,112 字节、
512 字节扇区、FAT32。仅操作专用新建测试文件，不格式化、不修复已有文件系统。

| 项目 | 结果与边界 |
| --- | --- |
| AC5 + TinyUSB 0.18 裸机 Host | 3 次启动的枚举、INQUIRY、首扇区读取通过 |
| FreeRTOS / RT-Thread Host | 两种模式分别通过枚举、INQUIRY、首扇区读取 |
| Host + FatFS：裸机 / FreeRTOS / RT-Thread | 三种模式分别创建、写入、跨扇区修改、追加、同步、重命名、重新挂载；66,153 字节逐字节校验通过，FNV32=DD7D393E |
| 复位后文件保留 | 三种模式均换为只读验证固件，重置后完整读回，块设备写计数为 0 |
| 用户实际断电后文件保留 | 用户确认所有连接同时断开至少 5 秒；恢复原接线后，不重烧、不格式化，以 FreeRTOS 只读固件完整核对 66,153 字节，写计数 0，通过 |
| FreeRTOS 诊断 | 栈检查 2、分配失败钩子开启，写测试通过；应用任务栈最小余量 1,024 字节，堆剩余 10,904 字节。这是该测试预算，不是通用最低值 |
| 工具全新自动生成 | AC5 Host 自动选 0.18、使用生成的 HAL 时基，全新生成工程实板文件验证通过 |
| AC6 6.22 + TinyUSB 0.21 | 裸机实板枚举、INQUIRY、首扇区读取通过；未据此宣称 AC6 全组件通过 |
| 软件 VBUS 断电循环 | **未通过**：原 Host 测试拉低 PA15 后 5 秒仍无断开事件；后续独立 GPIO/万用表对照中，PA15 实测低 0.01V、高 3.22V，但空载 USB3 两态均约 4V，未观察到有效关断。原因未定位，不作为物理断电通过 |

供电诊断使用 USB2 单路供电、USB1/USB3 空置、ST-Link 仅调试，无烧录或存储写入。
在测量前后核对 GPIO 模式及输入/输出读回：高态板上 5V/USB3 为 4.39V/4.05V，
低态为 4.33V/3.97V；另一次实际 PA15 高态 3.22V 时 USB3 为 3.93V。
这些是用户万用表读数，板上标称 5V 电源也偏低；尚未区分供电压降、开关电路、
旁路供电或板卡版本差异，不能断言 MOS 管损坏或将其归为 TinyUSB 软件缺陷。
首轮低态因配置曾恢复而排除，采用后续状态保持的复测；原始记录均保留。

本项属于 USB Host 的板级电源切换/故障恢复扩展验收，不等同于已通过的 U 盘文件读写。
按测试参与者决定，停止进一步元件级排查，不要求拆焊或继续测量小元件。
公开状态保留为“本测试板实测未通过，原因未定位”；其他板卡/供电开关组合未验证。
欢迎具备相应硬件与测量条件的贡献者复现并补充证据，不将本项标为“从未实测”。

首次恢复通信前 U 盘曾在电脑上重新插拔，因此不能把恢复完全归因于某一处代码修复。
失败固件、串口原始缺字和后续重测均保留。FreeRTOS 的两次真实断言分别揭示了调度器
启动前开 USB IRQ，以及测试 IRQ 优先级高于本工程允许范围。模板现将 RTOS USB 初始化
放入运行中的专用任务；板级 IRQ 按实际内核阈值换算。新模板的 USB Device 实板回归
已经改线后独立完成，见下一节；下方历史记录仍保留，不用旧固件结果代替新版本验证。

工具另修正了 AC5 DWC2 寄存器访问、只读一次的 RX 状态弹出、Host FIFO 区域重叠、
角色专用自动选版、毫秒时基，以及缺失控制器源文件的明确拒绝。11 项 TinyUSB 回归用例
与完整 18 个软件测试脚本通过。AC5 第三方源码仍有 3 条告警，原构建日志保留。

## 9 月 22 日新版 USB Device 初始化回归

USB1 接电脑、单路供电兼数据；USB2/USB3 空着，ST-Link 不接 5V。新生成的工程使用
改后的 RTOS USB 专用任务初始化流程。MSC 后端仅为 64 KiB 板内 RAM，不连接实体 U 盘、
SD 或 NOR。每轮写入前核对磁盘型号、序列号、USB 类型、容量及标识，只操作新建测试文件。

| 项目 | FreeRTOS | RT-Thread |

HID 未发送实际按键，不能宣称应用层键盘输入已验证。并发测试期间保留正常挂载心跳，

## 发现的问题与处理

- FreeRTOS 存储测试的轮询 SDIO 出现 `0x20` RX FIFO 溢出。板级测试改为 DMA、SRAM
  对齐中转缓冲及有界等待；首个 DMA 尝试仍有尾部未完成，改用外设流控并对齐后继续验证。
  这些是测试适配的修正，不是声称工具已内置通用 SDIO 驱动。
- 测试线程从 RT-Thread 迁到 FreeRTOS 后直接返回，调试器确认 `port.c:236` 的
  `prvTaskExitError` 断言；改为 `osThreadExit()` 后复测通过。默认生成的常驻任务本身已有循环。
- 裸机测试原 1 KiB 主栈失败，扩大为 8 KiB 后同套读写通过；HIL 栈预算并非所有工程默认值。
- 无线串口在首个 SD 读取后的日志固定缺开头字符。保留原始日志，增加板端检查结果重发、
  主机端完整行缓冲和全部编号核对；只收到汇总不判通过。不把链路缺字解释成文件系统损坏。
- RT-Thread 网络首次连接第一组 ping 有一次电脑端发送失败，原始失败保留；复位重测与
  压力测试通过。未将失败记录改成通过，也未用网络不相关的串口输出来证明传输正确。
- 一次 USB 测试启动时前一网络测试仍占串口，没有烧录；等待前一测试结束后重新测试通过。
  所有硬件测试必须串行占用设备。准备脚本的断言/参数错误同样保留，不混入通过结果。

新生成代码注释与中英文移植后教程补充了任务退出、SDIO 时序、DMA 内存和主栈注意事项。
本轮没有为了消除报错关闭断言，也没有把失败日志丢弃。第三方 AC5 警告仍记录在构建日志中。

## 不同类型的待办

“未覆盖全部硬件”不是一个可以打勾的单项：更换芯片、驱动、编译器、RTOS、组件版本或
内存布局，可能改变 IRQ、DMA、缓存与栈条件。已测配置可复现，但结果不能自动迁移。

| 项目 | 仍需要什么 |
| --- | --- |
| USB Host 扩展、真实 HID 输入 | U 盘基本链路和实际断电保留已通过；VBUS 关断实测未通过、原因待定位，其他 U 盘/Hub/HID 需对应验收 |
| IPv6、DHCP、MQTT、TLS | 独立网络服务/测试固件与协议级验收；本轮仅验证静态 IPv4、ICMP、UDP/TCP及适配层 |
| AC6、LVGL v9、更多裁剪组合 | 对应 SDK/工具链及独立构建和实板用例；不能沿用 AC5/LVGL8 的通过结果 |
| 其他 MCU/Flash/屏幕 | 对应硬件、接线和板级适配；本板无法验证 H7 DCache、M33 TrustZone 等行为 |
| 没有 Python/Git 的 Windows | 干净 Windows 机器或隔离虚拟机；本机限制 PATH 不等价于干净系统 |
| MDK6/CMSIS Solution、RTE/Pack、`.ioc` 同步 | 尚未提供的产品能力，不属于已支持功能的“测试通过”范围 |

原始证据仅本地留存，发布文档不包含用户路径、芯片 UID 或调试器序列号。
