# Git 版本管理

[English](GIT.en.md) · [界面指南](GUI.zh-CN.md)

点击底栏 **Git**。默认从当前选中的 Keil 工程定位仓库；如果工程位于已有
仓库子目录，显示实际仓库根目录，操作范围也是整个仓库。务必核对路径。
“其他工程”可以选择另一目录。手动修改路径后要先刷新，不能直接操作旧仓库。

## 第一次使用

需要 Git 2.23+（取消暂存使用 `git restore`）；建议采用官方安装器提供的受支持版本。

1. 没有 Git 时点击“安装 Git”，确认后打开官方安装流程。Windows 有 winget
   时启动交互式 Git.Git 安装；否则打开 Git 官方下载页。由你处理安装选项、
   管理员确认和协议。工具不会静默提权，也不关闭安全软件。
2. 安装完成点击“刷新 / 检测”。程序还会查找标准 Git 安装位置，不把“安装器
   已启动”当作安装成功。自定义安装目录未发现时，将 Git 加入 PATH 后重启工具。
3. 新工程选择“初始化仓库”。它只创建 Git 元数据，不自动提交；已有仓库不重复初始化。
4. “提交身份”设置本仓库的姓名、邮箱，不修改其他仓库的全局配置。身份会出现在提交中。
5. 可用“工程工具”生成基础 `.gitignore`，然后检查规则。不要提交密码、token、
   私有证书、庞大编译输出。Git 不是备份全部文件的替代品。

官方安装说明：[Git for Windows](https://git-scm.com/install/windows)。
winget 的精确软件 ID 安装方式见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)。

## 日常提交

1. 刷新，查看修改文件。XY 第一列是暂存区，第二列是工作区；`??` 表示未跟踪。
2. Ctrl/Shift 多选文件，点击“暂存所选”。取消暂存不会删除工作区文件。
3. “查看差异”显示已暂存、未暂存的文本差异；二进制文件不会显示像素级差异。
   未跟踪文件在暂存前不出现在 `git diff` 中，应自行检查内容。
4. 写清楚提交说明，点击“提交暂存区”，确认后提交 **整个暂存区**，包含其他工具
   之前已暂存的文件，不仅是列表当前选中的行。不会自动执行 `git add .`。
5. “提交历史”显示最近 30 次提交。

## 与远端同步

“配置远端”填写名称（通常 `origin`）和 HTTPS / SSH URL，也支持本地仓库路径。
不得在 URL 中包含密码或 token。首次认证请先在 Git/Git Credential Manager 中完成；
本工具不接管登录、不保存凭据。仅打开可信仓库：Git hooks、过滤器和凭据助手可能执行代码。

选择远端和远端分支，核对确认框中的地址。推送会列出 Git 的 push URL（可能不同于拉取地址）。

- 获取：下载远端引用，不合并工作区。
- 拉取：仅快进；有修改/未跟踪文件、分支分叉时拒绝，不自动 stash、rebase 或解决冲突。
- 推送：推送当前 HEAD 到指定远端分支，不使用强推。权限或认证失败会报告 Git 原始错误。

面板中的 Git 工作在后台线程，执行中禁止重复操作和关闭；网络操作超过 120 秒会报超时。
超时并不保证远端没有收到操作，必须刷新/核对后决定是否重试。断网或失败不会被伪装成成功。
目前不提供克隆、分支切换、合并冲突编辑器、撤销历史或强制覆盖按钮，需要时使用 Git 本身。

## 测试边界

自动化使用真实 Git、真实 Tk 按钮回调和临时仓库测试；本地裸仓库模拟远端，覆盖提交、
推送、拉取、脏工作区、分叉和拒绝推送。没有使用你的正式仓库测试上传。
“缺少 Git / 取消安装”采用模拟环境，不等于在一台全新 Windows 上完成安装验证。
真实 GitHub 账号登录、代理网络和管理员安装仍需对应环境验证。
