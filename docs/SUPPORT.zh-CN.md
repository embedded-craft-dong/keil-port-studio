# CubeMX/HAL 适配范围

[English](SUPPORT.en.md)

## 这版适合谁

本版主要面向 STM32CubeMX 生成的 STM32 HAL + Keil MDK `.uvprojx/.uvproj` 工程。
这是发布定位与验证边界，不是对任意 CubeMX 版本、芯片、板卡和组件组合的认证。
具体测试以[硬件矩阵](HARDWARE-MATRIX.zh-CN.md)记录为准，主要实板为 STM32F407。

| 工程或功能 | 本版边界 |
| --- | --- |
| CubeMX/HAL + Keil | 主要适配路径，仍需检查入口、时基、中断及板级驱动 |
| 标准外设库 SPL、自定义目录 | 基础工程管理可独立使用；自动移植与实板验收未完成 |
| RT-Thread | 当前为 Cortex-M4 单核、指定版本内核集成；不是完整 BSP/包管理 |
| CMSIS Solution、RTE/Pack 管理 | 不提供完整管理；不能用本工具代替官方生成器 |
| CubeMX `.ioc` | 不修改、不回写中间件选择；再次生成代码须自行合并并复测 |

## 操作前检查

1. 在工程副本或已提交 Git 的状态下操作；关闭 Keil，先确认原始工程能编译运行。
2. 检查选中的 Target、芯片和工具链。自动接入依赖 `Core/Src/main.c`、工程引用的中断文件
   以及 CubeMX `USER CODE` 标记；缺失、重复或补丁被拒绝时不要强行继续。
3. 先预览，再读完整警告。工具执行成功或编译成功，均不等于调度器、驱动和硬件运行通过。
4. 已由 CubeMX、RTE 或手工移植的中间件不要重复启用。确认唯一的调度器、SysTick/SVC/PendSV
   归属、USB 控制器及相关驱动；冲突检查不能覆盖所有自定义代码。
5. 按[移植后指导](POST-PORTING.zh-CN.md)实现硬件接口，再做功能、长时间运行和断电测试。
6. 再次使用 CubeMX 生成代码前备份；生成后检查工程引用、配置、启动和中断差异，重新编译与实测。
   `USER CODE` 标记不是所有工具修改都能被 CubeMX 保留的保证。

## 仍需公开的限制

- 标准库工程不是“不能运行这些中间件”，而是本工具的完整自动接入尚未验证；不要用添加标记代替适配。
- 测试板 USB3 VBUS 软件关断实测未通过，原因未定位；普通 U 盘读写与实际断电保留是另外的已通过项目。
- 无 Python/Git 的干净 Windows 验收未完成；EXE 未签名；GitHub Actions 需上传后实际运行。
- 中间件离线包尚未随本版提供；程序包与源码包不包含完整第三方 SDK。可按组件选择完整本地 SDK，
  缺少依赖时自动准备可能联网。不能把程序内“离线指南”理解为所有移植流程完全离线。

报告问题请使用仓库 Issue 模板并提供脱敏后的版本、Target、日志和复现步骤，不提交凭据或私人工程。
